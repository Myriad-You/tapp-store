# 共享签名板

`cn.astelysin.signature-board` 是一个 Myriad Tapp。访客可以浏览管理员发布的只读快照；已登录且加入专用公开 Room 的用户可以在 4096×2304 横向画布上绘制，并手动提交完整作品。

## 权限边界

- 普通成员只需要 `federation:read` 与 `federation:message`，不能创建、删除或管理 Room。
- `federation:room`、`storage:write` 仅供站点管理员初始化画板、维护封禁列表、审核作品和发布访客快照。
- 应用不修改 Myriad 源码。作品通过追加消息保存；普通成员无法修改或擦除已经提交的内容。
- 后画的作品可以在视觉上覆盖先前作品，但历史消息不会被删除。

Manifest 必须声明 `federation:room`，否则管理员也无法通过同一个 Tapp 创建和维护 Room；这意味着安装授权界面会展示这项高权限。应用只在确认当前角色为 owner/admin 后显示和调用管理入口，Myriad 服务端仍是最终权限边界。即使普通成员伪造 `moderator.hide` 消息，重放器也会按服务端信封 sender 拒绝它，因此不能借此修改公开画面。

不修改 Myriad 源码也带来一个明确后果：30 秒冷却、应用封禁和载荷格式首先由客户端执行。篡改客户端的人仍可能向 Room 写入垃圾原始消息，但合规签名板客户端会忽略无效、越界、非管理员审核或已封禁 actor 的事件。要在网络入口彻底阻止这类写入，需要未来增加服务端协议校验/速率限制；本版不会伪装成已经具备该保证。

## 使用

1. 管理员首次打开应用，点击“创建共享画板”。应用会创建一个专用公开 Room，并将 Room ID 写入 `Tapp.shared`。
2. 普通用户先在 Myriad 原生界面加入该 Room，再打开应用绘制和提交。
3. 管理员定期点击“发布访客快照”，让未登录访客看到最新压缩预览。
4. 占用率达到 80% 后，管理员可手动归档并创建新画板。

## 管理后台（v0.3.0）

管理员入口会打开 Tapp 内的全屏工作台，包含运行总览、举报与作品审核、Room 成员治理、活动画板与最近 6 块归档、权限和事件诊断。隐藏、恢复和处理举报全部写成追加事件，不修改或删除原始作品；成员治理只提供应用封禁、解除封禁和请求移出 Room，不提供角色变更。

“封禁并移出”有两层效果：合规客户端会过滤该 actor 的新旧作品，同时应用请求 Myriad 将其移出 Room。公开 Room 是否允许对方再次自行加入仍由宿主策略决定，因此后台会明确展示这一边界，不把客户端封禁描述为服务端永久封禁。

## 主页小组件（v0.4.0）

安装后可从主页小组件库添加“共享签名板”。小组件支持 `2x2` 和 `4x2`，默认使用适合横向画布的 `4x2`；它只读取管理员最近发布的 `Tapp.shared` 访客快照，展示画面、作品数、占用率和归档数，不加载完整 Canvas 编辑器，也不订阅 Federation Room。旧版快照仍可展示，但作品数与占用率会显示为未知，直到管理员重新发布快照。

当前 Myriad CLI 要求任何声明式 Widget 同时在 Manifest 声明 `widget:register`。本应用没有调用动态 `register` / `unregister` API；普通用户是否获得管理员专属的动态注册能力仍由宿主 Runtime Grant 决定。

历史页会列出最近 6 块已归档画布并读取各自的共享快照。为避免裁掉旧数据，从 `0.1.x` 升级时，已经存在的活动画布继续按 4096×4096 显示；完成一次归档后，新画布切换为 4096×2304。

## 本地检查

无需安装依赖：

```powershell
node tests/protocol.test.mjs
node tests/widget.test.mjs
node scripts/self-check.mjs
```

`preview.html` 是不依赖 Myriad Bridge 的静态界面预览。真实 Room 权限、加入、消息顺序和移除后重入行为必须在 Myriad 宿主内验收。
